9pwn/assembly: A brief 9front assembly tutorial

NOTE: this guide is for AMD64

So last time I rambled about how to do a ret2win in 9front (which you should read!). Today I wanna dive a bit into writing some assembly in 9front.

The Calling Conventions

Unlike Linux and BSD, 9front does not follow the System V ABI, so there are some differences in how the arguments are passed to the functions.

For syscalls:

syscall number: RBP
arg0: 0x8+RSP
arg1: 0x10+RSP
...

For libc functions:

arg0: RBP
arg1: 0x8+RSP
...

The return value is stored in RAX.

Making a quitter

Before you make a "quitter", have a look at /sys/src/libc/9syscall/sys.h as it has syscall numbers defined in it. For a quitter we need the void exits(char *msg) syscall which has the number 0x8

DATA msg+0(SB)/4, $"1337" // setup the exit status string, stored in the file
GLOBL msg(SB), $4 // make it visible to the linker

TEXT _main(SB), $0 // entry point
MOVQ $msg(SB), 0x8(SP) // setup arg0
MOVQ $0x8, BP // setup rbp for exits()
SYSCALL // execute the syscall

To assemble:

6a quitter.s

To link:

6l -o quitter quitter.6

Now when you run the program and check the status:

./quitter
echo $status
quitter 765: 1337

Explanation of the monstrosity above

Yes the syntax looks horrible, since I only knew Intel syntax this truly messed my brain. Anyways some questions I try to answer:

Why is it BP, SP, and AX instead of RBP, RSP and RAX? WHERE IS THE "R"?!?!?!

I ated it.

Ok but seriously it just isn't there. That's how the assembler is built. Prefixes are added to the instruction names instead:

B: 8bit (MOVB, ADDB etc)
W: 16bit (MOVW, ADDW etc)
L: 32bit (MOVL, ADDL etc)
Q: 64bit (MOVQ, ADDQ etc)

I actually like this approach more, I don't need to remember all the divisions of the registers.

What does 0x8(SP) mean?

0x8+rsp

What is SB?

Stands for static base and it is a pseudo register, bascially stores the virtual memory address where the binary will be loaded to.

Is the source and destination reversed?

Indeed, Intel syntax you would do

MOV RAX, 0x1337

But in 9front assembler syntax

MOVQ $0x1337, AX

What does msg+0(SB) mean?

Since SB is the address of the start of the binary, msg+0(SB) literally means msg+0+SB where msg is also an offset in the binary.

What is the $ symbol?

It means the intermediate value:

MOVQ $0x1337, AX // puts 0x1337 into RAX
MOVQ 0x1337, AX // finds whatever is stored at memory location 0x1337 and puts that into RAX

And

MOVQ $msg(SB), BP // put the value msg+SB into RBP
MOVQ msg(SB), BP // puts the value at msg+SB, in our case the string "1337"

Calling libc functions

Calling libc functions requires us to change up a few things, namely replacing _main with main and linking with /amd64/lib/libc.a and keeping and eye out on the calling conventions. Here is a simple program:

GLOBL buf(SB), $64 // define a 64 byte buffer in data segment

DATA msg+0(SB)/8, $"you said" // DATA directive only takes 8 bytes at once
DATA msg+8(SB)/2, $": " // so you need two definitions like this
GLOBL msg(SB), $8 // make it visble to the linker

TEXT main(SB), $0x20
// read(0, 64, buf)
MOVQ $0, BP // int fd (arg0)
MOVQ $buf(SB), 0x8(SP) // void *buf (arg1)
MOVQ $64, 0x10(SP) // long nbytes (arg2)
CALL read(SB)

//print("you said: ")
MOVQ $msg(SB), BP // (arg0)
CALL print(SB)

// print(buf)
MOVQ $buf(SB), BP // (arg0)
CALL print(SB)
// exit(0)
MOVQ $0, 8(SP) // (arg0)
MOVQ $8, BP
SYSCALL

Assemble (compile?) and link using:

6a printer.s
6l -o printer printer.6 /amd64/lib/libc.a
