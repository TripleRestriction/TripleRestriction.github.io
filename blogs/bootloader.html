Writing a bootloader was one of the things I always wanted to do. So I did it for my weekend project; it was difficult. I will assume you know assembly before we begin.

Some background

When the computer loads up it starts the BIOS (or the UEFI firmware) which performs certain hardware tests called POST. During POST the BIOS also finds the Master Boot Record (MBR), this MBR is what I have written, and managed to fit the entire bootloader in it.
The MBR is a 512 byte file (which is tiny!) that contains instructions on how to boot into the operating system. It must end with 0x55AA (or 0xAA55...endianness always messes with my brain).

Hello World

Ask BIOS to hello your world

[BITS 16]                       ; tell nasm to compile this part as 16 bit real mode machine code
[ORG 0x7c00]                    ; tell nasm that this file will load at 0x7c00

start:
    mov si, msg

print: 
    lodsb                       ; load byte by byte from data segment (ds) into al using si (ds:si)
    cmp al, 0                   ; check if character is a null byte
    je done
    mov ah, 0x0e                ; 0x0e = write character in tty
    int 0x10                    ; video interrupt
    jmp print

done:   
    hlt
 msg:
     db "Hello World", 0

;; pad the rest of the file
times 510-($-$$) db 0x67
dw 0xAA55

If you have written assembly Linux assembly with syscalls, you probably understand most of it. Compile and run using:

nasm -f bin boot.asm -o boot.bin
qemu-system-i386 -m 512 -drive format=raw,file=./boot.bin

You should see something like this: (I ran qemu with -nographic flag)

Linux Boot Protocol

How you write the bootloader depends on the kernel you are trying to load. The Linux kernel has a fixed boot protocol which you can find here.

First you need to get a bzImage or vmlinuz. You can compile it from the kernel source or get a super minimal one from my repo. The bzImage contains headers, legacy real mode code and setup code with the kernel in compressed format (xz, zstd or lzma depending on how it is compiled) which extracts itself as long as you jump to the setup code after meeting certain requirements...

For fun you can make a disk file using: 

dd if=/dev/zero of=./disk.img bs=1M count=10 # make a 10MiB disk image
dd if=./boot.bin of=./disk.img conv=notrunc # copy the bootloader into the disk image
dd if=./bzImage of=./disk.img bs=512 seek=4 conv=notrunc # copy the bzImage into the 5th sector (there is probably a better way to do this)
Then:
  • Clear out the registers (including segment registers) on boot
  • Unlock A20 line (allows access to more memory)
  • Load kernel headers from storage using Disk Access Packet structure into a (scratch) buffer
  • Zero out 4096 bytes of a memory region (our zero page)
  • Ask BIOS to put memory map in our zero page
  • Copy the kernel headers into the zero page and pass it bootloader ID and kernel command line
  • Create a global descriptor table structure and load it up using lgdt instruction
  • Enable protected mode by or-ing first bit of CR0 register
  • (Far) jump into 32 bit code and setup the registers
  • Read rest of the kernel (from the offset you are going to jump to) using ATA ports as you can't use BIOS interrupts anymore
  • Set ESI = address of your zero page
  • Jump into the kernel
